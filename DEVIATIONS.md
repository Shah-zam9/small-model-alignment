# Parameter Choices and Deviations Log

This file tracks all choices and deviations from the reference configuration in `docs/assignment_manual.pdf`, tagged as `[resource]` or `[performance]`.

| Stage / Setting | Guide Value | Value Used | Tag | Rationale & Evidence |
|---|---|---|---|---|
| Prompt Template | Student choice (consistent across SFT, DPO, eval) | `### Instruction:\n{instruction}\n\n### Response:\n` | `[performance]` | Clean single-turn delimiter structure compatible with base `Qwen/Qwen2.5-0.5B` without multi-turn chat special-token overhead. |
| SFT Loss Reduction | Mean of per-example summed NLL OR mean over unmasked response tokens | Mean over all unmasked response tokens in the batch (clamped denominator >= 1) | `[performance]` | Prevents long responses from dominating gradient norm and matches standard causal LM token-level cross-entropy scaling. |
| SFT Dataset Length Selection | 30,000 train / 1,000 val from `HuggingFaceH4/ultrachat_200k` | Sample 30,000 train (from 120,398) and 1,000 val (from 13,424) that fit in `<= 512` tokens with EOS | `[performance]` | In raw UltraChat, 42.07% of train examples exceed 512 tokens (which truncates off the EOS token and prevents learning clean stopping). Preferring examples that fit in 512 reduces EOS truncation in selected SFT data from 42.07% to 0.0%. |
| DPO Max Prompt Length (256) | Maximum prompt length = 256 | Filter out DPO pairs with formatted prompt > 256 tokens (instead of right-truncating prompt at 256) | `[performance]` | Right-truncating a prompt at 256 tokens cuts off the trailing `\n\n### Response:\n` delimiter, breaking prompt-response formatting. Filtering removes 203 train / 12 val pairs in HH-RLHF and 9,883 pairs in UltraFeedback `train_prefs`. |
| UltraFeedback Tied Score Filtering | 15,000 train / 1,000 val from `HuggingFaceH4/ultrafeedback_binarized` | Drop pairs with `score_chosen <= score_rejected` (7,286 dropped in `train_prefs`) before sampling | `[performance]` | Raw `ultrafeedback_binarized` contains 7,286 train pairs (including rows 0 and 1) where `score_chosen == score_rejected`. Removing zero-margin score ties eliminates conflicting preference supervision. |
| UltraFeedback 512-Token Length & Disjoint Split | 15,000 train / 1,000 val at `max_length=512` | Keep only pairs where BOTH `chosen` and `rejected` fit in `<= 512` tokens with EOS (new pool size: **29,594** after dropping 13,867 pairs > 512), and sample 15,000 train + 1,000 val disjointly from `train_prefs` (`seed=42`) | `[performance]` | Unfiltered UltraFeedback pairs had an asymmetric truncation rate at 512 tokens (**26.40% chosen** vs **18.61% rejected**), which biases summed sequence log-probabilities and strips EOS more frequently from chosen answers. Filtering to pairs where both fit in `<= 512` eliminates truncation asymmetry (0.0% vs 0.0%) and yields 29,594 clean pairs for disjoint 15k/1k train/val splits. |
| DPO Step-0 Mixed-Precision Baseline | Policy in `fp32` (`cuda:0`, `torch.amp.autocast(dtype=torch.float16)`) & frozen reference in `fp16` (`cuda:1`) | Keep exact manual precision layout (`policy=fp32+autocast`, `ref=fp16`); note step-0 numerical noise | `[resource]` | Because `policy_model` stores weights in `fp32` and uses `autocast(float16)` while `reference_model` stores weights directly in `fp16`, summed sequence log-probabilities at step 0 differ by $\sim 10^{-4}\text{--}10^{-3}$ due to floating-point rounding. Consequently, step-0 implicit rewards $\beta(\log\pi_\theta - \log\pi_{\text{ref}})$ are small numerical noise around $0$ (margin $\approx 0$, accuracy $\approx 0.50$) rather than exact bitwise zeros, while step-0 DPO loss remains $\approx \ln 2 \approx 0.6931$. |
