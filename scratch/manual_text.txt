Abstract
This assignment introduces the post-training pipeline used to turn a pretrained lan-
guage model into a more useful assistant. You will work with a small pretrained model,
Qwen/Qwen2.5-0.5B, and train it in two stages: supervised fine-tuning (SFT) on instruction-
response demonstrations, followed by Direct Preference Optimization (DPO) on pairwise
preference data. You will implement the main SFT and DPO training components yourself,
run the experiments on Kaggle T4 GPUs, generate responses on a fixed AlpacaEval subset,
and evaluate model behavior using pairwise judgments from Kaggle model APIs. The goal is
not to produce a state-of-the-art assistant, but to understand the mechanics, tradeoffs, and
evaluation challenges of modern LLM alignment.

2 High-Level Background
2.1 Pretraining
Modern language models are first trained with a self-supervised next-token prediction objective.
Given a sequence of tokens x1, . . . , xT , the model learns to maximize
T∑
t=1
log pθ(xt | x<t). (1)
This stage teaches the model broad linguistic, factual, and reasoning patterns from large text
corpora. However, a pretrained base model is not necessarily a good assistant. It may continue
text, imitate undesired formats, fail to follow instructions reliably, or produce unsafe content.
In this assignment, you will not pretrain a model. You will start from a pretrained base model,
Qwen/Qwen2.5-0.5B, and study post-training.
2.2 Supervised Fine-Tuning
Supervised fine-tuning (SFT), also called instruction tuning, trains the model on examples of the
form:
instruction → response.
The model is trained with teacher forcing to assign high probability to the target response. A key
implementation detail is that the loss should usually be applied only to response tokens, not to the
prompt tokens. If x is the instruction prompt and y is the target response, the SFT objective is
LSFT(θ) = − log πθ(y | x). (2)
SFT teaches a base model to follow an instruction-response format and to imitate high-quality
demonstrations.

2.3 RLHF
Reinforcement Learning from Human Feedback (RLHF) typically involves three stages:
1. Train an SFT model from demonstrations.
2. Train a reward model from pairwise human preferences.
3. Optimize the language model policy against the reward model, often using PPO with a KL
penalty.
RLHF is powerful but complex. It requires reward modeling, online sampling, reinforcement learn-
ing machinery, and careful stabilization. Within this broad framework, this assignment focuses
on two pieces: supervised fine-tuning (SFT) and policy optimization. For the policy-optimization
stage, you will use Direct Preference Optimization (DPO) instead of PPO.
You will not implement PPO or a full reward-model-based RLHF pipeline in this assignment.
Instead, you will implement DPO, a simpler preference-learning method.
2.4 Direct Preference Optimization
Direct Preference Optimization (DPO) is a preference-learning method introduced by Rafailov et
al. in Direct Preference Optimization: Your Language Model is Secretly a Reward Model . It is
designed to get many of the benefits of PPO-style policy optimization while avoiding the most
complicated parts of a PPO-style reinforcement learning pipeline.
The data for DPO is pairwise. Each training example contains:
instruction x, chosen response yw, rejected response yl.
The chosen response is the answer a human or preference dataset judged better. The rejected
response is a worse answer to the same instruction. DPO does not ask the model to imitate only
the chosen response. Instead, it asks the model to make the chosen response more likely than the
rejected response, while staying close to a frozen reference model.
2.4.1 Why DPO Needs a Reference Model
If we only pushed the policy to prefer chosen responses over rejected responses, the model could
drift too far from the SFT model. That can produce strange outputs, repetition, overconfident
refusals, or loss of general helpfulness. DPO therefore compares two models:
▶ the policy model πθ, which is trainable;
▶ the reference model πref , which is frozen and usually initialized from the same SFT checkpoint.
The reference model acts like an anchor. DPO rewards the policy for improving the chosen-vs-
rejected preference relative to what the SFT model already believed . This is the part that replaces
the explicit KL penalty used in many RLHF pipelines.
2.4.2 The Loss, Intuitively
For each pair, compute four response log probabilities:

log πθ(yw | x) policy log probability of the chosen response

log πref (yw | x) reference log probability of the chosen response
log πref (yl | x) reference log probability of the rejected response
Then compare two preference gaps:
∆θ = log πθ(yw | x) − log πθ(yl | x), (3)
∆ref = log πref (yw | x) − log πref (yl | x). (4)
∆θ says how much the trainable model prefers the chosen response over the rejected response. ∆ref
says how much the original SFT model already preferred the chosen response. DPO trains the
policy so that ∆θ becomes larger than ∆ref .
The per-example DPO loss is:
LDPO = − log σ (β [(log πθ(yw | x) − log πθ(yl | x)) − (log πref (yw | x) − log πref (yl | x))]) . (5)
Equivalently:

The hyperparameter β controls the strength of the reference-model constraint in the DPO
formulation. A larger β penalizes deviation from the reference policy more strongly, while a smaller
β permits greater deviation. It also scales the logits inside the logistic loss, so changing it changes
the optimization dynamics as well as the effective regularization. In this assignment, β = 0.1 is the
recommended starting point.
DPO in One Sentence
DPO teaches the model to increase the probability gap between preferred and rejected
answers, measured relative to a frozen SFT reference model, without training a separate
reward model or running online reinforcement learning.
2.4.3 Step-by-Step DPO T raining
A single DPO update looks like this:
1. Format the instruction x exactly the same way for both the chosen and rejected response.
2. Tokenize the prompt-response sequence for yw and for yl.
3. Mask prompt tokens so that log probabilities are summed only over response tokens.
4. Run the trainable policy model on the chosen and rejected sequences.
5. Run the frozen reference model on the same chosen and rejected sequences with gradients dis-
abled.
6. Sum token log probabilities over the response span for each sequence.

7. Compute the policy preference gap ∆θ and the reference preference gap ∆ref .
8. Apply the DPO logistic loss − log σ(β(∆θ − ∆ref )).
9. Backpropagate only through the policy model.
10. Repeat with gradient accumulation, validation, and checkpointing.
The important implementation idea is that DPO is still ordinary supervised optimization over
saved data. There is no environment, no online sampling loop, and no separate reward-model
training stage.

A practical workflow is:

2. Clone the repository in Kaggle.
3. Run training in one notebook.

10.5 Metrics
For each validation pair, define the implicit rewards:
rw = β (log πθ(yw | x) − log πref (yw | x)) , (7)
rl = β (log πθ(yl | x) − log πref (yl | x)) . (8)
Reward accuracy is the fraction of validation examples where
rw > r l. (9)

Reward margin is the mean value of
rw − rl. (10)
If the policy and reference models are initially identical, every reward pair is tied: rw = rl = 0 .
Because reward accuracy uses the strict comparison rw > r l, its exact initial value is then 0, not
0.5. After the policy begins to move away from the reference, an accuracy near 0.5 with a margin
near 0 suggests no consistent preference direction. Higher reward accuracy with a positive margin
suggests the policy is learning to prefer chosen responses.

13.2 Evaluator Reliability Requirements
Your evaluator should:
